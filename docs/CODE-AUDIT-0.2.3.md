# Проверка кода 0.2.3

## Исправлено

- Чтение бинарного RouterOS API ограничено по размеру слова (8 МиБ), предложения (16 МиБ), числу слов (65536), общему размеру ответа (64 МиБ) и числу предложений (50000); некорректные префиксы длины отклоняются, переполнение на 32-битных системах предотвращено. Короткие записи больше не считаются успешными. Очень большие легитимные ответы теперь могут быть отклонены.
- HTTP POST к API принимает только JSON и, если браузер прислал Origin, требует соответствия хосту запроса. Это блокирует обычные межсайтовые формы и чужой Origin, но не является аутентификацией, не защищает от вредоносных локальных программ или полностью от DNS rebinding. При стандартном запуске сервер слушает loopback; не открывайте его в недоверенной сети с `-addr`.
- Пул DHCP не может включать адрес роутера, сети или broadcast; подсети /31 и /32 для DHCP отклоняются. Неверные IPv4-адреса и маски больше не заменяются молча другими значениями при нормализации.

## Ограничения

- Автоматические тесты, mock-серверы и сборки не заменяют проверку команд на реальных устройствах и версиях RouterOS. Применение скрипта не атомарно: после ошибки часть настроек может уже существовать. Перед применением создайте резервную копию и проверьте текст скрипта.
- Ранее выявленное несоответствие модели hAP ac3 и показаний CHR, а также причины переключений LTE не установлены. См. DEVICE-DISCOVERY-AUDIT.md и FAILOVER-STAND-BASELINE.md.
- Клиент RouterOS допускает самоподписанные TLS-сертификаты без проверки подлинности и совместимость со старым TLS; обычный API без TLS не шифрует учётные данные. Используйте доверенную сеть и проверяйте адрес назначения.
- MAC-Telnet и Android WebView/установка подписанного обновления требуют проверки на реальных устройствах; текущая проверка не доказывает отсутствие всех ошибок и уязвимостей.
