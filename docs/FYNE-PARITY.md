# Перенос HTML → Fyne: инвентаризация на 0.4.0

Сверено с `web/index.html`, маршрутами `internal/server/server.go` и текущими
`fyneapp/cmd/inspector`. Это инвентаризация возможностей интерфейса, **не**
подтверждение работы на реальном устройстве. Общее Go-ядро само по себе не
означает перенос формы или сценария. «Частично» означает, что остаются пробелы;
Fyne не является полной заменой HTML. Используйте HTML-версию для отсутствующих
сценариев. Обе программы имеют ограничения функциональности RouterOS.

| HTML-возможность | Fyne | Что осталось |
|---|---|---|
| Подключение auto/API/REST/MAC, TLS, информация, модель, прошивка, пакеты, источники модели, копирование | Частично | Проверить отдельное форматирование и все пользовательские сценарии, Windows и реальное устройство; поиск устройства и подключение к новому отдельно ниже |
| Обнаружение MikroTik в сети и подключение к заводскому адресу одной кнопкой | Нет | Перенести discovery, предупреждения/ограничения и действие подключения |
| Сохранённые устройства: CRUD, выбор, импорт/экспорт JSON без паролей | Частично | Общий файл и валидатор, импорт/экспорт и подстановка с очисткой пароля; автоматические тесты, визуальная проверка Windows остаётся |
| Снимок сети, выбор bridge/VLAN, аренды, история failover, однократное LTE, копирование | Частично | Есть чтение и копирование текстового отчёта; отсутствуют сохранение файлов, интерфейс сравнения и LAN-анализ ниже. Снимок частичный и неатомарный |

| OpenVPN сертификаты и клиент, экспорт профиля | Нет | Перенос форм и безопасного экспорта секретов |

| PPTP клиент | Нет | Перенести форму и предупреждение об устаревшем протоколе |
| WAN основной/резервный, DHCP/static/LTE, failover | Нет | Перенести форму, опции, предупреждения и план; сохраняются ограничения ядра |

## Правила завершения переноса

Для каждой строки нужны сопоставление полей/сценариев HTML, вызовы общего ядра,
валидация, тесты успешных и отрицательных сценариев, обработка устаревших данных
и ошибок, а для записи — явное подтверждение и предупреждения об отсутствии
атомарности/отката. Нужны сборка и визуальная проверка Windows, проверка на
подходящем тестовом RouterOS и безопасная проверка результата. До выполнения
этих пунктов обозначать поддержку как частичную, а не объявлять полный паритет.
Приоритет: снимки, затем формы конструктора и отдельные guarded
операции; каждый рискованный раздел переносить и проверять отдельно.
