Подключение к роутеру

Поиск MNDP работает в локальном L2-сегменте и может блокироваться Wi‑Fi или брандмауэром. Данные соседей не проверяются. В поле «Адрес роутера» можно указать MAC-адрес (например, AA:BB:CC:DD:EE:FF) — Inspector подключится по MAC (MAC-Telnet), как WinBox → Neighbors, без IP; протокол MAC-Telnet выберется автоматически. Для MAC-подключения компьютер должен быть в том же L2-сегменте, а на роутере должен быть включён MAC-Telnet/MAC-WinBox на разрешённых интерфейсах.
Порты по умолчанию: RouterOS API — 8728 (с TLS — 8729), REST API — 80 (с TLS — 443). Рекомендуется включить в RouterOS /ip service api/rest и входить под администратором. Данные подключения используются и для применения конфигурации. Кнопка «Подключиться к новому MikroTik» использует 192.168.88.1, admin, пустой пароль, автоматический выбор API/REST и порты по умолчанию без TLS. Подключите компьютер к LAN-порту и убедитесь, что API или REST включён. На некоторых моделях пароль указан на наклейке; при сбросе без заводской конфигурации адрес и сервисы могут отсутствовать. В этих случаях введите свои данные или используйте WinBox.

Безопасность
Опасность потери доступа! Сначала выключите остальные разделы конструктора: защита применяется отдельным скриптом. Укажите ВСЕ внешние интерфейсы, включая PPPoE; в доверенные адреса включите свой текущий IP и локальную сеть управления. Защита не охватывает невыбранные интерфейсы и транзитный трафик. IPv6 WinBox не разрешён. Из WAN остаются только WinBox с доверенных адресов, существующие соединения и служебный DHCP/ICMPv6. Входящие VPN и проброс доступа к сервисам роутера будут заблокированы. MAC-WinBox и другие сервисы управления (включая API/REST) отключаются глобально — приложение потеряет подключение. Скрипт можно только скопировать и выполнить в WinBox New Terminal с включённым Safe Mode. Это не замена аудиту и резервной копии.
Доступ к ресурсам за NAT
Страны можно не выбирать, если указаны отдельные адреса.
Выключите другие разделы: это отдельный скрипт для одного существующего dst-nat, он не создаёт проброс. Правила затрагивают только выбранный WAN, внутренний IPv4, порт и протокол; их accept имеет приоритет над существующими правилами. Все пробросы на этот внутренний адрес и порт через выбранный WAN попадут под правило, независимо от внешнего порта. IPv6, непроброшенные соединения и другие WAN не защищены. Уже работающие FastTrack-соединения могут сохраняться до очистки conntrack. Для каждого другого ресурса используйте отдельный идентификатор. Страны определяются по RIR-делегированию адресов: геолокация приблизительная, VPN/proxy её обходят. Обновляйте список вручную (кэш данных — 12 часов). Кнопка «Применить» для этого раздела отключена. Большие скрипты загружайте как .rsc и импортируйте локально; Safe Mode не рассчитан на тысячи изменений.
Резервное копирование
Предварительно настройте /tool e-mail (SMTP, TLS, логин, пароль приложения) и отправьте тестовое письмо на самом роутере. Установите точное время и часовой пояс. Пароль бэкапа виден в скрипте и хранится на роутере; сохраните его отдельно. Не публикуйте скрипт. Перед каждым запуском старый mti-scheduled.backup удаляется, даже если создание нового не удастся; храните независимые копии. Новый файл остаётся на роутере; доставка письма не гарантируется — проверьте почту и журнал. Повторное применение заменяет задания mti-backup. Проверяйте восстановление на совместимом устройстве.
VPN
WireGuard использует только UDP. Порты можно изменить; порт сервера в клиенте должен совпадать с локальным портом сервера. Ключи создайте заранее. На сервере разрешите входящий UDP-порт; маршруты и firewall на обеих сторонах настройте отдельно. Создаётся один peer. Повторное применение требует ручного удаления созданного интерфейса.

На сервере разрешите входящий UDP-порт; маршруты и firewall на обеих сторонах настройте отдельно. Создаётся один peer. Повторное применение требует ручного удаления созданного интерфейса.
Запускайте на серверном MikroTik с точным временем. Создаются новый CA, серверный и один клиентский сертификат; существующий CA не используется. Сервер OpenVPN не включается автоматически. Пароль попадёт в скрипт. Файлы CA и PKCS12 передавайте клиенту защищённо, затем удалите PKCS12 с роутера. Повторное применение остановится, если сертификаты mti-ovpn уже существуют.
Выбор действует для MikroTik и экспортируемого профиля. Маршруты, получаемые от VPN-сервера, отключены: маршруты к удалённым сетям добавьте вручную. При выходе через VPN проверьте приоритеты существующих маршрутов и настройте NAT на сервере; равные приоритеты могут направлять трафик через WAN. При обрыве VPN возможен выход через WAN; это не kill switch. DNS и IPv6 настраиваются отдельно.
Для OpenVPN 2.6+. Файл содержит логин, пароль и при выборе PKCS12 — закрытый ключ. Передавайте и храните его защищённо. Пароль PKCS12 клиент запросит при подключении.
TCP или UDP и порт должны совпадать с настройками сервера. Режим IP, AES-256-CBC / SHA1; сервер должен поддерживать эти параметры. Импортируйте доверенный CA и при необходимости клиентский сертификат до применения. Маршруты и firewall настраиваются отдельно. Повторное применение требует ручного удаления подключения.
PPTP устарел и небезопасен; по возможности используйте WireGuard. Маршруты и firewall настраиваются отдельно. Повторное применение требует ручного удаления подключения.
Интернет → WAN

Основной и необязательный резервный провайдер: LTE или проводной (DHCP / статический IPv4). Для PPPoE пока используется отдельный раздел. VLAN провайдера нужно создать заранее.

Проверка каждые 5 секунд. При включении нужны два провайдера. Проверка основного продолжается на резерве. ICMP роутера к этому узлу закрепляется за основным каналом.

Без контроля интернета: DHCP реагирует на потерю lease/link; ping шлюза проверяет только шлюз. Контрольный узел должен отвечать на ICMP. Существующий DHCP-клиент выбранного порта будет включён и обновлён: default route, distance и отключение peer DNS. Его комментарий сохраняется. Проверьте существующие маршруты перед применением. Настройки DNS задаются отдельно. Снятие галочки не удаляет ранее применённые настройки.

IP → Firewall → NAT

Каждое правило открывает доступ к локальному сервису. Без ограничения источника — для всего интернета. Проверьте порядок NAT и разрешение dstnat в цепочке forward: firewall автоматически не меняется.

Hairpin требует фиксированный внешний IPv4 и подсеть LAN. Для динамического IP используйте внутренний DNS. Повторное применение заменяет только правила mti-forward-*. Снятие галочки не удаляет настройки с роутера.
